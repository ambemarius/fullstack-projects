# Invitation acceptance returns to login

27 October 2026. Owner requests that successful acceptance show success and take the teacher directly to login, without redisplaying the administrator acceptance form. **Deployed on the canonical listener.**

The public acceptance route now completes the role grant, one-time token consumption, account security-version increment, revocation of all recipient opaque sessions and audit in one transaction. A per-account application lock serializes reauthentication-required acceptance, so simultaneous requests cannot both grant or deadlock while revoking the same sessions. Failed audit/validation rolls back the whole operation. Only successful responses clear the Secure/HttpOnly/SameSite cookie. The original runtime's existing credential-version checks also reject the recipient's pre-acceptance legacy tokens. Passwords and other accounts are unchanged.

Frontend clears the pasted token and cached invitation data, then uses location.replace to return to `/?invitation=accepted&accountType=teacher` (or the existing administrator profile type). The login page selects the appropriate existing type, keeps a visible success message and removes the one-time feedback query from history. No token, email, password or redirect target supplied by a caller goes into the URL. No second logout network call is needed, so a committed grant cannot be stranded on the invitation form by a later logout failure. Teachers continue to use their existing credentials.

Already-admin staff no longer see the acceptance panel when revisiting the invitation page; they see an existing-access notice. Platform operators retain their issue/list/revoke panel. Ordinary failed/rejected acceptance does not redirect or display false success.
