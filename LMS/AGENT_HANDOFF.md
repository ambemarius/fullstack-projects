## Project purpose

Cameroon-oriented secondary-school management: student/staff registration, Anglophone/Francophone classes, academic years, subjects, assignments, timetables, marks, report cards, and promotion. A separate MCQ exam API supports automatic grading and admin-published results. This is primarily school administration; no learning-content platform was found.

## Actual implementation

- Node.js/CommonJS, Express 5, Microsoft SQL Server (`mssql`), handwritten SQL.
- EJS + CSS + plain browser JavaScript. README's React/Vite reference is stale.
- Admin, teacher, student JWT accounts; auxiliary staff are admin-managed records.
- 21 seeded classes, 23 table definitions, three terms and two sequence marks per term.
- Main admin interface: `views/admin-layout.ejs` and `public/js/admin-layout.js`.
- Finance has fee records/settings but its main tab is a placeholder. Exam APIs are not a complete dashboard exam experience.

## Fixes to prioritize

1. JWT secret is hardcoded, token contains only ID, and middlewares interpret that ID in independent role tables. Fix signing configuration and signed account type together.
2. Admin registration is public.
3. Setup creates subjects/classes before referenced teacher/class tables.
4. Marks pass student/offering IDs in reverse order to enrollment model methods.
5. Teacher marks/exam access lacks assignment/ownership scope; student exams lack class/year eligibility.
6. Student list selects `s.*` and returns password hashes.
7. Validate mark numeric ranges/maxima, membership, and year; protect batch writes.
8. Reports use current class/year, so promotion can remove students from historical reports. Year junctions and student fields disagree; subject unenrollment affects every year.
9. Normalize grading only after agreeing school policy. Online exam scores and sequence scores are separate systems.
10. Add transaction/collision protection for timetable replacement/manual entry; remove production stack traces.

## Important domain details

`class_subjects` is the class/subject offering; teacher assignments add term but no year; student offering enrollment adds year. Reports use offering coefficients. Subject creation is catalog-only; allocations ensure an offering exists. Timetable generation is greedy, uses the first co-teacher, and deletes then inserts. Promotion moves by rank, without result thresholds; rank-7 graduation is a promotion flag.
